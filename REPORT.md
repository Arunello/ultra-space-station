# Отчёт по проекту «Космическая станция»

## 1. Цель работы

Разработать программу на Java для управления модулями космической станции. Реализовать иерархию классов, паттерны проектирования «Абстрактная фабрика» и «Итератор», а также операции копирования, перемещения и удаления модулей.

## 2. Структура проекта

Основные классы программы:

* `Station` — хранит модули станции и предоставляет методы для работы с ними.
* `Module` — базовый абстрактный класс модуля.
* `ResidentialModule`, `EnergyModule`, `ResearchModule` — категории модулей.
* `CrewCabin`, `MedicalCabin`, `SolarModule`, `ReactorModule`, `BiologyLab`, `PhysicsLab` — конкретные типы модулей.
* `Durability`, `EnergyConsumption`, `Capacity` — хранят характеристики модулей.
* `ModuleFactory` — интерфейс фабрики.
* `StandardModuleFactory`, `AdvancedModuleFactory` — создают стандартные и улучшенные модули.
* `StationIterator` — обеспечивает перебор модулей станции.
* `Main` — демонстрирует работу программы.

## 3. UML-диаграмма классов

Диаграмма показывает наследование классов, связи между станцией и модулями, а также реализацию фабрик и итератора.

## 4. Паттерн «Абстрактная фабрика»

**Абстрактная фабрика** — паттерн проектирования, который позволяет создавать объекты через общий интерфейс, не указывая их конкретные классы в клиентском коде.

В проекте интерфейс `ModuleFactory` определяет методы создания жилых, энергетических и исследовательских модулей.

Реализованы две фабрики:

* `StandardModuleFactory` создаёт `CrewCabin`, `SolarModule` и `BiologyLab`.
* `AdvancedModuleFactory` создаёт `MedicalCabin`, `ReactorModule` и `PhysicsLab`.

Фабрика выбирается в клиентском коде, после чего создание модулей выполняется через её методы.

Преимущество паттерна — возможность менять набор создаваемых реализаций без необходимости переписывать код, который использует фабрику.

## 5. Паттерн «Итератор»

**Итератор** — паттерн, позволяющий последовательно перебирать элементы коллекции, не обращаясь напрямую к её внутреннему устройству.

Класс `Station` реализует интерфейс `Iterable<Module>`, а внутренний класс `StationIterator` реализует `Iterator<Module>`.

Итератор предоставляет два основных метода:

* `hasNext()` — проверяет, есть ли следующий элемент.
* `next()` — возвращает следующий элемент.

Благодаря этому модули можно перебирать с помощью цикла:

```java
for (Module module : station) {
    System.out.println(module.getName());
}
```

## 6. Копирование и передача модулей

В проекте предусмотрено копирование станции и её модулей.

Конструктор `Station(Station other)` создаёт новую станцию с копиями модулей. Метод `copyFrom()` позволяет заменить содержимое одной станции копиями модулей другой.

При копировании модулей создаются отдельные объекты характеристик `Durability`, `EnergyConsumption` и `Capacity`. Поэтому изменение характеристик копии не влияет на исходный модуль.

Копии получают новые ID. Это позволяет избежать конфликтов идентификаторов, когда исходные модули и их копии впоследствии находятся на одной станции.

Методы `transferModuleTo()` и `transferFrom()` предназначены для передачи модулей между станциями. Перед передачей проверяется вместимость принимающей станции.

### Правило пяти

Правило пяти (Rule of Five) относится к C++ и описывает пять специальных функций, связанных с управлением ресурсами и копированием объектов: деструктор, конструктор копирования, оператор копирующего присваивания, конструктор перемещения и оператор перемещающего присваивания.

В Java это правило не применяется буквально, поскольку управление памятью выполняет сборщик мусора. В данном проекте реализованы аналогичные по назначению операции копирования и передачи объектов средствами Java.

## 7. Результаты демонстрационных сценариев

В классе `Main` представлены следующие сценарии.

**Сценарий 1. Создание модулей.** Создаются жилой, энергетический и исследовательский модули. Они добавляются на станцию и выводятся вместе со своими характеристиками.

**Сценарий 2. Копирование станции.** Создаётся копия станции, из неё удаляется модуль, изменяются характеристики других модулей и добавляется новый модуль. Затем выводятся исходная станция и изменённая копия.

**Сценарий 3. Передача модулей.** Модули из копии передаются на исходную станцию. Передача выполняется с учётом доступной вместимости.

**Сценарий 4. Управление модулями.** Демонстрируются активация, деактивация, изменение состояния и перемещение модулей внутри станции.

**Сценарий 5. Удаление и ограничение вместимости.** Модули удаляются по ID и индексу. Также демонстрируется обработка попытки добавить модуль на заполненную станцию.

В совокупности сценарии демонстрируют основные возможности программы: создание, хранение, копирование, изменение и передачу модулей.

## 8. Выводы

В ходе работы разработана модель космической станции с использованием объектно-ориентированного программирования на Java.

Реализованы иерархия модулей, фабрики для создания объектов, итератор для перебора коллекции и операции управления содержимым станции.

Абстрактная фабрика отделяет создание объектов от клиентского кода, а итератор упрощает перебор модулей. Копирование позволяет создавать независимые экземпляры модулей, а передача между станциями учитывает ограничение вместимости.

Проект демонстрирует применение наследования, абстракции, полиморфизма и паттернов проектирования на практическом примере.
